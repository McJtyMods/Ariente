ARIENTE - FORGE 1.20.1 PORT HANDOFF
Updated: 2026-10-30

STATUS AND PURPOSE
==================
This is an INCOMPLETE development port, not a completed gameplay port or a
release candidate. Both mods build and substantial world generation/rendering
work is active, but survival progression and several equipment features are
still missing. Passing builds and focused tests do not establish feature parity.

This file owns Ariente gameplay, machines, equipment, shared HoloGui work,
resources/recipes, rendering and packaging. Read ../ArienteWorld/PORTING.txt for
the dimension, cities, population, travel generation, city AI and editing tools.
Both documents are intended to let a future Codex session resume without chat
history. Phase 1 equipment implementation and focused validation are recorded
below; this does not establish full survival progression or multiplayer parity.

ACTIVE IMPLEMENTATION - DO NOT RE-PORT THESE FROM SCRATCH
=======================================================
Foundation and systems
- Registry/capability/network/tag/recipe/datagen APIs compile for the target.
  Recipe lookup and recipe-ID propagation were repaired. Original assets remain.
- McJtyLib-based tile infrastructure and HoloGui integration are active.
  Multipart support was recovered from McJtyLib history into Ariente's own
  package; it still needs deeper gameplay validation.
- Power networks, generators, tanks, storage, constructors, automation nodes,
  doors, wireless devices and security code are present. Presence does NOT mean
  all options, progression paths and edge cases have been verified.
- Persistence checks cover 31 registered block entity types. Fixed generator
  remaining-fuel saves, Lock settings, node filters/routing colors and parent
  owner/security saves. Storage Cube, Blueprint Storage and Auto Constructor
  inventories round-trip. Normal save/reload correctness remains required.

Rendering, synchronization and interactions already repaired
- Storage Cube front items/counts and ForceField settings synchronize, including
  initial chunk data. ForceField unload no longer sends unsafe updates while
  saving. Shield panel bounds refresh when client settings change.
- Cables derive visible connections from neighbors. Connector housings and
  machine-contact plates render in cutout, with facade layers preserved.
  Atlas references refresh after resource reload. Cable beam rendering EXISTS;
  old notes saying it is wholly unported are stale.
- Native connected texture quarters and emissive cutout overlays are active.
  Ramps/slopes render, including upside-down slopes, and do not occlude the
  neighboring solid faces. Straight/curved Flux Beam outlines match geometry.
  Flux Beams intentionally have no collision, as in the original mod.
- Automatic doors use their marker's orientation and synchronize animation,
  opening, collision and locks. Authored marker orientation is handled by the
  companion's CityFeature (wide openings and single ship doors).
- Flat Light and Alarm selection shapes match their distinct models for all
  six facings. AI cores have an opaque frame and translucent green glass.
- Tanks have opaque frames, joined stack rims and sorted translucent glass.
  A single broad animated beam per section faces the camera around Y only.
  Glass and beams share the native sorted buffer; vertical UVs align across
  stacks. Existing textures are reused. Inventory models retain both layers.
- Soldier/drone/sentinel models render. Unnamed drones no longer show type labels.
  Combat drones use mob line of sight instead of the incompatible Brain helper.
  Lasers emit buffered beam geometry and move their collision bounds correctly.
- Levitator and elevator cabins render, passenger positioning no longer recurses,
  and mounted levitator controls render through their actual entity renderer.
  This does NOT cover the separate Flux Ship renderer, which is still disabled.
- Warper/Elevator HoloGui entities are pickable without physically obstructing
  the player and lowering the camera. Elevator height settings synchronize and
  invalidate cached beam bounds. Ariente Pearls implement ItemSupplier and use
  a typed vanilla thrown-item renderer; their previous rendering crash is fixed.
- Warper return destination/charges and dimension travel have server checks.
  The companion owns generated entrances and arrival structures.
- Power suits use the original 64x128 texture and custom geometry through a
  modern armor client extension. All four pieces follow humanoid poses.
  Movement modules are now active too; see phase-1 equipment checks below.

Shared HoloGui implementation in ../ModHoloGui
- Panels render before widgets with depth writes; widgets sit in front of the
  panel. Images use unlit native shaders. An isolated buffer keeps widget order
  independent of deferred world buffers, and translucent item icons stay with
  the panel in Fabulous graphics. Glass/shields behind panels no longer overdraw
  their face in the checked scenes.
- GUI item transforms, vertex tinting for unavailable items, transformed border
  quads and proper depth replace old leaking texture/light/GL-state operations.
  Default StyledColor.LABEL is dark purple (0xff201850), including Pwr labels.
- Armor screens have Mod / On / Key labels and boxed activation toggles.
  Click a module ITEM ICON to install/remove it using inventory items, then the
  adjacent On box to enable it; Key selects a hotkey group. Equip the armor first
  or hold the Enhanced Energy Sabre in the main hand. Default configure key: 0.
- Install/enable/hotkey/fuel mutations synchronize inventory/equipment. Removing
  a module clears module, working and hotkey keys; stale screens reject unrelated
  equipment. Server and integrated-client removal checks now pass, including
  pixel comparisons.

PHASE 1 - EQUIPMENT IMPLEMENTED AND FOCUSED CHECKS PASSED
=======================================================
- ArmorGui activation and hotkey columns moved right/up in panel coordinates,
  with their hit boxes. Both column groups use the same offsets. HoloStackToggle
  now renders installed modules bright/bordered, available inventory modules at
  55% brightness and unavailable modules at 25%. Removing a module visibly dims
  it, clears module/working/hotkey state and returns the inventory item.
- ClientForgeEventHandlers restores Space thrust, Flight+Hover altitude hold,
  sneak descent and forward/back Speed with separate configured ground/air caps.
  Horizontal caps no longer scale vertical velocity. Hover remains active while
  opening a GUI; thrust/acceleration keys do not. Riding, swimming, elytra and
  creative flight keep their normal movement. No creative-flight ability is set.
- Step Assist adds 1.302 through Forge's step-height attribute (normal player
  height becomes 1.902), using its own stable modifier UUID. Other modifiers are
  preserved. Armor Improvement also uses stable per-slot UUIDs.
- Server player ticks reset only the powered Flight wearer's floating timeout
  and fall distance. The timeout field is exposed by Ariente's access transformer;
  server-wide flight permission and player abilities are unchanged. Losing Flight
  restores ordinary falling; working Feather Falling boots still prevent damage.
- PowerSuit ticks check the actual worn stack by identity, preventing a backpack
  copy at a coincidentally matching inventory index from consuming fuel or working.
  All installed modules get consistent working flags; power/budget failure clears
  Scramble and every other effect. Disabled/removed modules cannot remain working.
- ModuleSupport autofeed first locates all missing fuel components, then consumes
  a pair atomically. Split holders, one shared holder, loose dust and mixed local/
  inventory fuel work without wasting surplus local dust. Each charged pair now
  lasts exactly max(1, configuredTicks / usage) working ticks. Hotkeys accept only
  groups 1..4 and installed modules; toggling clears stale working state.
- PowerSuitEffects tracks suit-owned Night Vision/Invisibility/Regeneration,
  removing them on disable, power loss, unequip, death and logout. Pre-existing
  potion effects are left in control; effects that replace the suit's effect are
  preserved, including a weaker vanilla hidden effect when our effect is removed.
  Invisibility's original disabled install control remains disabled.
- Enhanced Sabre works in the actual main hand in any hotbar slot. Backpack and
  offhand copies stop working. Looting/Fire module boosts preserve unrelated
  enchantments and restore their recorded original levels on disable, exhaustion,
  removal or changing hands. Power/Inhibit use the same working-state lifecycle.

Focused evidence and remaining limits
- Dedicated suite: all 29 required tests passed, including five new
  EquipmentRegressionTests for identity/exhaustion, atomic fuel, budgets/hotkeys,
  sabre slots/enchantments and potion ownership. Existing GUI tests cover removal.
- EquipmentMovementClientChecks (opt in: ariente.equipmentMovementCheck=true)
  ran in survival with allow-flight=false: actual ascent, 120-tick hover, descent,
  Flight hotkey off, Speed vs unequipped movement (6.96 vs 4.06 blocks/20 ticks),

  after fuel exhaustion. This driver edits an isolated arena and exits on success.
- ArmorClientChecks plus ariente.armorGuiStateCheck=true verify actual server/
  client install-enable-hotkey-remove inventory/NBT, then exit on success.
  HologramRenderingChecks compare installed/removed pixels at five angles and
  check panel/control visibility and glass/shield depth before/after reload.
  Final GUI checks passed in vanilla Fabulous and Embeddium 0.3.31/Oculus 1.8.0
  Fancy, without a shader pack.
- Artifacts: ../ArienteWorld/build/verification/armor-module-{installed,removed}-*.png.
  Use the companion's isolated client setup; do not run fixtures in player worlds.
- Still required: dedicated multiplayer/reconnect/death play tests, backward/

PHASE 2 - RESOURCE AND CRAFTING PROGRESSION CHECKPOINT
=====================================================
- All seven Ariente resource ores have loot, strength and stone-tier pickaxe
  requirements. Metal/fuel ores drop themselves; the four metals smelt/blast to
  one ingot, and Negarite/Posirite smelt/blast to four dust (original conversions,
  200/100 ticks, zero XP). Silicon drops silicon with native Fortune/Silk Touch
  behavior. Silicon processing was absent even in master; this direct drop
  deliberately closes that original material-obtainability gap.
- Original soldier/drone/sentinel lithium tables are restored under data/ariente,
  retaining player-kill gating and 50% + 1% per Looting level chance. Soldier's
  modern loot hook is active; Master Soldiers inherit it. Existing security-card
  drops and last-core storage-access cards remain separate.
- Optional Overworld generation uses a registered native feature/configured/
  placed feature plus an Overworld biome modifier. Original vein size ranges,
  attempts and Y ranges are retained, including white marble. The runtime guard
  honors OVERWORLD_OREGEN YES/NO/DEFAULT and the actual Overworld dimension.
  DEFAULT enables it only without ArienteWorld; no retrogen was added.
- The inactive onLootLoad handler was removed. A registered global loot modifier
  handles the original seven chest-table families and reads server config at roll
  time. It preserves vanilla loot and offers one weighted extra selection: weight
  100 for no addition, configured blueprint/result weights, and six equipment
  entries each with the configured suit weight. Default 20/0/0 gives a 1-in-6
  blueprint opportunity per chest, then the original weighted recipe catalog.
  This additive adaptation does not claim identical old main-pool roll behavior.
- Negarite/Posirite/Combined cable and connector recipes now use their distinct
  item registrations. IDs and blueprint matching are distinct; connector inputs
  require the matching cable. Data cable/connector recipes were absent in master
  and remain absent. Manual crafting uses the recipe's canonical batch count,
  regardless of the count encoded in a blueprint. Invalid blueprint JSON returns
  an empty result instead of crashing the GUI.
- Both Constructors reserve each ingredient once (including repeated ingredients
  across split stacks). Auto Constructor uses full result counts for new/existing
  output, requires space for the whole batch in one output slot, and consumes
  ingredients only after crafting power is available. Output slots reject input.
- JEI 15's Constructor category shows counted ingredients, full output and the
  required blueprint as a catalyst; Constructor and Auto Constructor are machine
  catalysts. Blueprint subtypes resolve by recipe ID. Creative/JEI lists include
  a populated blueprint per catalog entry. Obsolete JEI wrappers and imperative
  ModCrafting initialization were removed; processing lives in generated data.
- Companion city loot now uses module_looting instead of nonexistent module_loot.
  Explicit blueprints for original recipe-less modules (Power, Regeneration,
  Scramble, Speed, Step Assist) and a silver-ingot blueprint were changed to the
  existing item drops. These are usable loot routes, not new recipes. Hover has
  no catalog recipe or confirmed authored loot entry; Invisibility's original
  disabled install control remains. Do not claim every module is survival-ready.

ORIGINAL UNFINISHED BEHAVIOR - NOT ALL OF THIS IS A PORT REGRESSION
================================================================
The following also existed in master. Preserve the distinction between porting
existing behavior and designing a feature that was never finished:
- Invisibility's helmet install control was disabled (effect/item code exists).
- Blueprint recipes were absent for several registered modules, including Speed,
  Hover, Step Assist, Power, Regeneration and Scramble. Audit full obtainability;
  do not claim all missing recipes were lost during this port.

  did too. Decide/fix operation gating as completeness work, not a new regression.
- Cable beams render regardless of actual power; combined-cable beam rendering
  returns early in master as well. Existing individual cable beams are ported.
- Arbitrary player-facing key-card programming was not a complete original
  workflow; authored city/security-card setup is active.

  Perform full survival/multiplayer/long-route tests, full datagen/resource audit,
  standalone and workspace dependency validation, and release metadata review.
  Exit: clear evidence of feature coverage and remaining limitations, not merely
  a successful compilation. Keep both PORTING files and the guide current.
