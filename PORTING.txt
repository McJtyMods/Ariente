ARIENTE - FORGE 1.20.1 PORT HANDOFF
Updated: 2026-10-30

STATUS AND PURPOSE
==================
This is an INCOMPLETE development port, not a completed gameplay port or a
release candidate. Both mods build and substantial world generation/rendering
work is active, but survival progression and several equipment features are
still missing. Passing builds and focused tests do not establish feature parity.

This file owns Ariente gameplay, machines, equipment, shared HoloGui work,
resources/recipes, rendering and packaging. Read ../ArienteWorld/PORTING.txt for
the dimension, cities, population, travel generation, city AI and editing tools.
Both documents are intended to let a future Codex session resume without chat
history. The latest armor reports below are OPEN; investigation has not yet
produced implementation changes for them.

ACTIVE IMPLEMENTATION - DO NOT RE-PORT THESE FROM SCRATCH
=======================================================
Foundation and systems
- Registry/capability/network/tag/recipe/datagen APIs compile for the target.
  Recipe lookup and recipe-ID propagation were repaired. Original assets remain.
- McJtyLib-based tile infrastructure and HoloGui integration are active.
  Multipart support was recovered from McJtyLib history into Ariente's own
  package; it still needs deeper gameplay validation.
- Power networks, generators, tanks, storage, constructors, automation nodes,
  doors, wireless devices and security code are present. Presence does NOT mean
  all options, progression paths and edge cases have been verified.
- Persistence checks cover 31 registered block entity types. Fixed generator
  remaining-fuel saves, Lock settings, node filters/routing colors and parent
  owner/security saves. Storage Cube, Blueprint Storage and Auto Constructor
  inventories round-trip. Normal save/reload correctness remains required.

Rendering, synchronization and interactions already repaired
- Storage Cube front items/counts and ForceField settings synchronize, including
  initial chunk data. ForceField unload no longer sends unsafe updates while
  saving. Shield panel bounds refresh when client settings change.
- Cables derive visible connections from neighbors. Connector housings and
  machine-contact plates render in cutout, with facade layers preserved.
  Atlas references refresh after resource reload. Cable beam rendering EXISTS;
  old notes saying it is wholly unported are stale.
- Native connected texture quarters and emissive cutout overlays are active.
  Ramps/slopes render, including upside-down slopes, and do not occlude the
  neighboring solid faces. Straight/curved Flux Beam outlines match geometry.
  Flux Beams intentionally have no collision, as in the original mod.
- Automatic doors use their marker's orientation and synchronize animation,
  opening, collision and locks. Authored marker orientation is handled by the
  companion's CityFeature (wide openings and single ship doors).
- Flat Light and Alarm selection shapes match their distinct models for all
  six facings. AI cores have an opaque frame and translucent green glass.
- Tanks have opaque frames, joined stack rims and sorted translucent glass.
  A single broad animated beam per section faces the camera around Y only.
  Glass and beams share the native sorted buffer; vertical UVs align across
  stacks. Existing textures are reused. Inventory models retain both layers.
- Soldier/drone/sentinel models render. Unnamed drones no longer show type labels.
  Combat drones use mob line of sight instead of the incompatible Brain helper.
  Lasers emit buffered beam geometry and move their collision bounds correctly.
- Levitator and elevator cabins render, passenger positioning no longer recurses,
  and mounted levitator controls render through their actual entity renderer.
  This does NOT cover the separate Flux Ship renderer, which is still disabled.
- Warper/Elevator HoloGui entities are pickable without physically obstructing
  the player and lowering the camera. Elevator height settings synchronize and
  invalidate cached beam bounds. Ariente Pearls implement ItemSupplier and use
  a typed vanilla thrown-item renderer; their previous rendering crash is fixed.
- Warper return destination/charges and dimension travel have server checks.
  The companion owns generated entrances and arrival structures.
- Power suits use the original 64x128 texture and custom geometry through a
  modern armor client extension. All four pieces follow humanoid poses.
  Armor MODELS are restored; armor MOVEMENT is not.

Shared HoloGui implementation in ../ModHoloGui
- Panels render before widgets with depth writes; widgets sit in front of the
  panel. Images use unlit native shaders. An isolated buffer keeps widget order
  independent of deferred world buffers, and translucent item icons stay with
  the panel in Fabulous graphics. Glass/shields behind panels no longer overdraw
  their face in the checked scenes.
- GUI item transforms, vertex tinting for unavailable items, transformed border
  quads and proper depth replace old leaking texture/light/GL-state operations.
  Default StyledColor.LABEL is dark purple (0xff201850), including Pwr labels.
- Armor screens have Mod / On / Key labels and boxed activation toggles.
  Click a module ITEM ICON to install/remove it using inventory items, then the
  adjacent On box to enable it; Key selects a hotkey group. Equip the armor first
  or hold the Enhanced Energy Sabre in the main hand. Default configure key: 0.
- Install/enable/hotkey/fuel mutations synchronize inventory/equipment. Removing
  a module clears module, working and hotkey keys; stale screens reject unrelated
  equipment. Server tests pass, but the latest removal-HIGHLIGHT report is open.

CONFIRMED MISSING PORTS / INCOMPLETE MIGRATIONS
============================================
Equipment and effect lifecycle
- ClientForgeEventHandlers.java: restore Flight/Hover/Speed/Step Assist from
  master using current APIs. Original intent: Space supplies upward thrust;
  Flight+Hover holds height; sneak descends while hovering; Speed accelerates
  forward/back with separate ground/air caps; boots raise step height (legacy
  value 1.902). Do not silently replace this with unrelated creative-flight
  behavior. Handle server movement validation, fall behavior and synchronization.
  Respect other mods' attributes/abilities and remove only Ariente's changes.
- PowerSuit.java and items/modules/ModuleSupport.java: audit enabled vs installed
  vs working state, budgets, fuel exhaustion, toggling/removal, unequipping,
  death/reconnect, attributes, potion effects, fall protection and Scramble.
  On helmet power failure Scramble is not explicitly cleared; verify/correct
  stale working flags. Nightvision/regeneration code exists; do not call every
  module unimplemented just because movement is absent.
- EnhancedEnergySabreItem.inventoryTick compares a hotbar inventory index with
  MAINHAND.getIndex() (0), so it updates only the first slot and does not properly
  establish that this stack is held. Test other slots, offhand, fuel loss and
  built-in looting/fire enchantment updates without erasing unrelated enchants.
- ModuleSupport.checkAutofeed extracts holder posirite from negariteStack rather
  than posiriteStack. Fix the mixed-holder path and check atomic fuel-pair use.
- Do not misdiagnose PowerSuit's index check as the same sabre bug: vanilla
  Inventory.tick supplies per-compartment indices, including armor indices.
  Test the actual worn stack; backpack copies must not supply equipped effects.
- Each gear piece has its own fuel. Default budget is 100, or 130 with Energy
  enabled; one dust pair supplies about 30000/usage ticks (40000/usage optimized).
  Fuel and working-flag code being present does not implement movement itself.

  do not claim all missing recipes were lost during this port.

- Arbitrary player-facing key-card programming was not a complete original
  workflow; authored city/security-card setup is active.
